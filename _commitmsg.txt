界面精简：砍掉两栏板与拖动，胶囊改小改圆，清掉堆叠文案

用户原话：提示词管理和提示词组合功能重叠、不需要拖动、为什么要有「可用提示词」框、
提示文字太多看着很乱；胶囊开关点不动、样式是方胶囊不是椭圆胶囊。

一、胶囊开关点不动 —— 这个是**真 bug，而且不在前端**

编辑器拨开关的流程是：
  POST /state {enabled} → 成功后 load() 重新 GET /edit
  → setEnabledDraft(d.enabled !== false)

而 /edit 的响应里**根本没有 enabled 字段**，d.enabled 是 undefined，
`undefined !== false` 恒为 true —— 刚拨下去就被读回 true。
POST 一直成功、磁盘也写对了，只有界面读不回来。

修：GET /edit 补 `enabled: readState().enabled !== false`。
（用 readState() 而不是 injector.isEnabled() —— 测试里的假注入器没有那个方法。）

二、胶囊样式：方胶囊 → 小椭圆

它是 `<button>` 做的（为了键盘可达），所以必须自己压掉浏览器默认按钮外观 ——
不写 appearance / boxSizing / margin 的话，borderRadius 被 UA 外观盖住，
得到的就是个方按钮。尺寸 34×20 → 30×18，滑块行程 18px → 14px。
（这一条是推断，我无法在真机上看渲染结果；如果还是方的，请把截图发我。）

三、两栏板（生效 / 可用）删掉，合成一列勾选

两栏是**同一批条目**的两个视图 —— 一条提示词要么在这边要么在那边，
占两倍宽度却不增加信息。现在一列：已选的排前面（按真实注入顺序），
每条显示 名字 / order / token 数，顶部一行「已选 N 条 · 共 X tokens」。

四、拖动删掉

顺序根本不是这里定的 —— 每条提示词有自己的 order，dsh 按它排。
两栏板能「拖出顺序」纯粹是它给人的错觉。
连带删掉：dragOver 状态、onDragStart/onDragOver/onDragLeave/onDrop、
computeOrder（它只做 ids.slice()，空壳）、以及那句「勾选或拖动」文案。

五、页脚四条并列说明 → 一行

原来堆了：order 怎么算 / 哪层生效 / 保存后会发生什么 / 正文写在哪。
叠在一起就是一片灰字。现在只留「正文写在 …」——
order 的解释在每条卡片的详情里本来就有（title 里也写着）。
主开关下面那段两行说明也压成一行。

测试：删掉测两栏板/拖动的断言，换成**反向**断言（不许再出现「可用（」「拖动」
「order 决定插入位置」），避免它们悄悄长回来。

顺带修一个测试自己的坑：总开关那组断言用 `[...base, v]` 覆盖 enabledDraft，
而 base 已经是「到 enabledDraft 之前的全部」—— 再 append 就跑到它后面去了，
等于没覆盖。删掉 dragSt 那个槽、下标前移一位之后才暴露出来。
改成按位置替换（withEnabled(v)），不再数下标。
